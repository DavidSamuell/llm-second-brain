# Caddy + oauth2-proxy (`INGRESS=caddy`)

For a server with a public IP address. Caddy gets Let's Encrypt certificates and serves both hostnames. oauth2-proxy asks people to sign in with your identity provider (Google, Microsoft, GitHub or any OIDC provider) before they reach the editor. The MCP host is passed straight through, because vault-mcp authenticates every request itself.

What you need:

- A server with ports **80 and 443** reachable from the internet (80 is for Let's Encrypt and redirects).
- DNS `A`/`AAAA` records for two hostnames pointing at the server, e.g. `docs.example.com` (editor) and `docs-mcp.example.com` (agents).
- An OAuth app at your identity provider for the editor login (below).

## 1. Create the editor login app

The redirect URL is `https://docs.example.com/oauth2/callback` (your `IGNIS_HOST`).

- **Google:** Google Cloud console → APIs & Services → Credentials → *Create credentials → OAuth client ID* → Web application. Add the redirect URL. `OAUTH_PROVIDER=google`.
- **Microsoft Entra ID:** App registrations → New registration → Web redirect URI. Create a client secret. `OAUTH_PROVIDER=entra-id` (oauth2-proxy also needs `OAUTH2_PROXY_OIDC_ISSUER_URL`; add it to `ingress/caddy/compose.yml` environment).
- **GitHub:** Settings → Developer settings → OAuth Apps → New. Callback URL as above. `OAUTH_PROVIDER=github`.

`OAUTH_ALLOWED_EMAIL_DOMAINS` limits who gets in (e.g. `example.com`; `*` allows any account the provider accepts, which you almost never want).

This login is only for people using the editor. Agents connecting through Claude.ai or ChatGPT sign in through vault-mcp's own OAuth (`OAUTH_UPSTREAM_*`, see docs/SETUP.md); that can reuse the same identity provider with a second OAuth app whose redirect URL is `https://docs-mcp.example.com/oauth/callback`.

## 2. Configure the kit

```bash
scripts/setup     # choose INGRESS=caddy and answer the questions
```

or in `.env`, then `scripts/setup --non-interactive`:

```bash
INGRESS=caddy
DOMAIN=example.com
IGNIS_HOST=docs.example.com
MCP_HOST=docs-mcp.example.com
ACME_EMAIL=ops@example.com            # Let's Encrypt account / expiry mails
OAUTH_PROVIDER=google
OAUTH_CLIENT_ID=…
OAUTH_CLIENT_SECRET=…
OAUTH_ALLOWED_EMAIL_DOMAINS=example.com
# OAUTH_COOKIE_SECRET is generated by setup
MCP_OAUTH_ISSUER=https://docs-mcp.example.com   # setup fills this in
```

Setup sets `COMPOSE_FILE=docker-compose.yml:ingress/caddy/compose.yml`. Caddy publishes 80/443 on all interfaces; `BIND_ADDR` stays `127.0.0.1`, so the raw `IGNIS_PORT`/`MCP_PORT` are never public. If the server runs a firewall, allow 80/tcp, 443/tcp and 443/udp only.

The configuration lives in `ingress/caddy/Caddyfile`:

- `IGNIS_HOST`: `/oauth2/*` goes to oauth2-proxy. Everything else first passes Caddy's `forward_auth` against oauth2-proxy (unauthenticated → redirect to sign-in), then goes to Ignis. WebSockets pass through.
- `MCP_HOST`: everything goes to vault-mcp, with no login and streaming responses flushed immediately.

## Requirements checklist (§5.1)

| Requirement | How this profile meets it |
|---|---|
| 1. HTTPS | Caddy gets and renews Let's Encrypt certificates for both hostnames automatically; HTTP redirects to HTTPS. |
| 2. WebSockets on the editor | `reverse_proxy ignis:8080` upgrades WebSocket connections; `forward_auth` checks the session cookie first. |
| 3. Login before the editor | `forward_auth` → oauth2-proxy `/oauth2/auth`; no valid session → redirect to `/oauth2/sign_in`; only `OAUTH_ALLOWED_EMAIL_DOMAINS`. |
| 4. MCP host without interactive login | The `MCP_HOST` block has no `forward_auth`; the whole host goes to vault-mcp. |
| 5. Raw ports not exposed | Only Caddy publishes ports; Ignis and vault-mcp are bound to `127.0.0.1` and reached over the compose network. |

## Verify

```bash
token=$(scripts/token create --name exposure-check --owner you@example.com --scope read --expires 1h | grep -o 'vmcp_[A-Za-z0-9_-]*')
CHECK_TOKEN=$token scripts/check-exposure https://docs.example.com https://docs-mcp.example.com
scripts/token revoke exposure-check
```

Run it on the server, and once from another machine to confirm the raw ports are closed (`nc -zv <server> 8081 8082` should fail). In a private browser window, `https://docs.example.com` should send you to your provider's sign-in; an address outside `OAUTH_ALLOWED_EMAIL_DOMAINS` should be refused.

## Troubleshooting

- **Certificate errors on first start:** DNS must point at this server, and port 80 must be open, before Caddy can get certificates (`docker compose logs caddy`).
- **Sign-in loops:** `IGNIS_HOST` must match the browser's host exactly; the callback URL at the provider must be `https://IGNIS_HOST/oauth2/callback`.
- **Editor stays "connecting":** something in front of Caddy (a CDN, a load balancer) drops WebSockets.
